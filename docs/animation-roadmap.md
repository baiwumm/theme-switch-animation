## 1. 四条不可谈判的约束

任何候选先过这四关，过不了直接进 §4 不做清单：

1. **只用 mask 动画。** Safari 忽略 view-transition 伪元素上的 `clip-path` 与 WAAPI，所以不碰 transform / clip-path / CSS filter 动画。唯一例外是 `CIRCLE_BLUR`——它的高斯模糊是 `feGaussianBlur` 烘焙进 SVG 蒙版本身，不是 CSS filter。
2. **末帧必须完全覆盖。** 注入的样式在转场结束后还要延迟 `duration` 才清理，蒙版期间持续生效（`fill: both`）。任何"末帧仍留镂空或半透明"的方案都不可接受。这条已经否掉了 FAN 的软尾（改成硬边）和 DISSOLVE 的朴素做法。
3. **转场期只有伪元素能动。** 真实页面被冻结，JS 驱动的装饰动画不会播放；转场前插进 DOM 的东西会被拍进旧截图。所以一切效果必须是纯 CSS 蒙版几何。
4. **任意单帧必须能与同类项区分。** 只在时间维度做文章的候选（错时 / 反向 / 变速 / 缓动差异）一律先按退化处理，除非它改变的是**静止帧的拓扑**。750ms 的转场不给用户解析"节奏不同"的时间，而同类项的参数滑杆通常已经覆盖了那种差异。这条否掉了 `SPIRAL`（撞 CLOCK_SWEEP）与 `COMB`（撞 BLINDS），是本轮才提炼出来的——前两次的失败当时只记成"观感不达标"，没归纳成判据。

## 2. 现有 15 种覆盖了哪些维度

| 维度 | 已覆盖 | 缺口 |
| --- | --- | --- |
| 起点 | 触发点向外（CIRCLE 家族 7 + RIPPLE + CLOCK_SWEEP + FAN）、全屏轴推进（BLINDS / SCAN / QR_GRID）、中线对称推开（CURTAIN）；`reverse` 补上收拢侧——四处向触发点收拢、`CURTAIN` 向中线合拢 | 多中心 / 错时 —— SEEDS 试过已撤，判定为纯 mask 下的天花板；条带分批错时（COMB）也已撤，见 §4 |
| 前缘形态 | 硬边、软边、高斯模糊边、环带回摆、旋转射线 | 碎粒边（DISSOLVE，被约束 2 卡住） |
| 推进量 | 半径（`<length>`）、轴平移（`<length>`）、逐格生长（`<length>`）、角度（`<angle>`） | ~~半径 × 角度联动~~ SPIRAL 试过、观感撞脸已撤 |
| 轮廓来源 | 内置 SVG 多边形 | **用户自定义轮廓**（P2-2，要先定消毒规则） |
| 方向 | 四向（`direction`）、通用反向（`reverse`，9 个类型接入） | 未接入 `reverse` 的 6 个类型：形状族其余 3 个（斜线轮廓无静止盒子绕路，§4），`BLINDS` / `SCAN` / `QR_GRID` 由 `direction` 占那根轴 |

**结论**：形状族（7 个）已经饱和，再加多边形只是同质堆叠。真正稀缺的是**多中心**、**半径×角度联动**、**自定义轮廓**这三条。

## 3. 执行顺序

状态取值：`待做` / `进行中` / `已落地` / `已撤回`。

### P0-1 `CURTAIN` 双开门

| 项 | 内容 |
| --- | --- |
| 观感 | 新主题从屏幕中线向两侧对称揭开，像拉开幕布 |
| 机制增量 | **无** |
| 实现要点 | `masks.ts` 里 `centerBandGradient`（现已与 CURTAIN 主层合并共用）本来就是"从中心向两侧对称生长"的写法，把它从格子逻辑里拎出来当独立蒙版即可；蒙版盒子静止、复用 `REVEAL_VAR` |
| 参数面 | 不加。`direction` 对它静默无效（与 RIPPLE / CLOCK_SWEEP 一致） |
| 待验点 | **中缝接缝已实测排除**（headless Chrome 冻结进度截图）：r=640 时实心段精确落在 320→960、中缝无可见接缝、两侧 24px 软边对称；末帧整平面实心。起始帧中缝透出一道约 ±24px 的光，是加分观感而非缺陷。**仍未验**：分数缩放 dpr 下中缝与软边会不会出现 1px 级亮暗线 |
| 状态 | **已落地（v1.9）**：core + 画廊第 16 张卡 + 10 例单测 + 探针实测 + 全部门面同步。遗留的分数缩放 dpr 一档已于 v1.15 在 headless（dsf 1.25 / 1.5 + clean 变体）核销——仅起始帧中缝透光的设计基线，无伪影；OS 整屏缩放的真机档仍等使用者反馈（见 next-steps §2） |

**为什么排第一**：最不可能失败，先用它把"做一个 → 量一次 → 验一次 → 提交"的节奏跑顺。

### P0-2 `SPIRAL` 螺旋扫开

| 项 | 内容 |
| --- | --- |
| 观感 | 射线一边绕轴心转、一边向外长，新主题呈螺旋铺满 |
| 机制增量 | 一个 keyframes 里同时动两个注册属性（`SWEEP_VAR` + `REVEAL_VAR`）；两正交蒙版层求交 |
| 实现要点 | "角度已扫过 **∩** 半径已长出"= conic 层与 radial 层用 `mask-composite: intersect`——这正是 QR_GRID 已跑通的路子（含 `@supports (mask-composite: intersect)` 门控）。降级基线取半径层（观感退化成 CIRCLE） |
| 参数面 | 建议不加。若要"螺距"就得第二个参数，先不做 |
| 待验点 | **两个 `@property` 同 keyframes 插值——实测成立**（`<angle>` 与 `<length>` 各自线性推进，25% 时 `90deg` / `204px`）。**踩到一个必须记住的坑**：半径终值取 `2.1 × maxRadius`（照抄 CIRCLE）会让半径在动画 47% 处就盖满、后半程只剩 conic 起作用、观感退化成 CLOCK_SWEEP；取 `maxRadius` 则末帧四角落在软边 transparent 上直接露底。定稿 `maxRadius × 1.05 + 软边`。根因是语义差异：CIRCLE 的 `2.1` 是给 **`mask-size` 的边长**用的（圆半径 = 边长/2），而 radial-gradient 里的变量**直接就是半径**，套同一系数等于白给 2.1 倍冗余 |
| 状态 | **已撤回（2026-09-23）**。需求方真机判定："这个确实像 CLOCK_SWEEP，效果一般"。技术全部成立（双层 intersect 渲染、两属性插值、末帧盖满都实测通过），**败在观感辨识度**——"一条射线 + 一段圆弧外沿"在 750ms 下读起来还是"扇形在转"，与 CLOCK_SWEEP 的区分度撑不起第四个 builder 的成本。源码已 `git checkout` 全撤，未进任何提交 |

**撤回后不要再重提 SPIRAL**，除非能找到让"半径维度"在视觉上真正压过"角度维度"的编排（比如半径与角度非线性联动、或让圆弧外沿带可见的粗度变化）。同理，任何"conic ∩ radial"类的组合都继承了这个问题——两个约束里总有一个会先饱和。

**辨识度最高的一个**，机制全是已验证两块的组合，但比 P0-1 多一层不确定性。

### P1-3 `SEEDS` 多点错时扩散

| 项 | 内容 |
| --- | --- |
| 观感 | 屏幕上 3~4 处先后各自长出圆斑，陆续拼满，像墨点渗透 |
| 机制增量 | **无**（多层 radial + 错时） |
| 实现要点 | 多个 `radial-gradient` 图层，各层进度写成 `calc(var(--theme-switch-reveal) - 偏移px)` 错开，层间默认 `mask-composite: add` 求并集（**不需要 `@supports` 门控**，add 是初始值）。落进现成的 `isRevealAnimationType` / `getRevealMaskSpec` 分发，`orchestrate.ts` 与 `styles.ts` 零改动 |
| 参数面 | 种子数与错时量全部固化为常量（`SEED_GRID_COLS/ROWS` = 2×2、`SEED_STAGGER_RATIO` = 0.4、`SEED_EDGE_FEATHER_PX` = 20）。**错时量必须按格外接圆的比例而不是固定 px**——固定 px 在窄屏上会占到终值七成以上，最后一块几乎到动画末尾才开始 |
| 待验点 | **三条实测修正**：① 触发点**不能**当种子之一——它会让四层的覆盖划分变成不规则，每层外接圆算不准、某角必留缝；定稿规则 2×2 格中心、不消费 `ref` 几何。② **每层必须用 `min()` 钳在自己的格上限**。第一版漏了钳制，四层都随 var 无限制长大，首层在动画中段半径就超过整个视口半对角，并集之下把后面三层完全遮蔽——真机反馈"只有两个格"就是这个。钳制是 SEEDS 成立的前提而非调优，已写成断言（`to > cap` + 串里必须含 `min(`）。③ 末帧覆盖的数学依据是"每层实心段 = 所在格外接圆 × 1.05"，圆盖住整格、四格并集即盖满视口。**新知识**：`min(var(--x), Npx)` 在动画中逐帧重新求值（解析后的 maskImage 里已无 `min(`），库产出的三层嵌套 `calc(min(calc(var - 151px), 416px) - 20px)` Chromium 接受 |
| 状态 | **已撤回（2026-09-23）**。钳制修好了"只有两个格"的 bug（四点层次实测可见），但真机判定整体观感仍不理想：圆斑越界交叠形成的形状读起来不像"渗透"，更像"几个大气泡互相吞并"。**结论：多中心方向在纯 CSS 蒙版下撞到天花板**——圆不能无缝铺矩形，要干净就得引入区域裁剪（每层再叠一个矩形 intersect），成本翻倍且又会踩回 SPIRAL 那类"两个约束互相遮蔽"的问题。源码已 `git checkout` 全撤，未进任何提交 |

**给后续多层类型的通用教训（仍然有效）**：只要用 `mask-composite: add` 求并集，就必须给每层一个**上限**（`min()`）——并集不是"叠加显示"而是"取最大"，最快那层会遮蔽后面所有层。`min(var(--x), Npx)` 实测在动画中逐帧重新求值（解析后 maskImage 里已无 `min(`），三层嵌套 `calc(min(calc(var - 151px), 416px) - 20px)` Chromium 接受。`QR_GRID` 没踩到这个坑是因为它用 `intersect`（取交）。
**当时以为这条也顺带解释了为什么 P1-4 不受影响**：奇偶两批条带的空间区域天然不重叠，每层只在自己的条带里有 alpha，所以不存在"最快层遮蔽后面层"。这个判断**是对的但不重要**——COMB 确实没踩并集遮蔽，它死在别处（撞约束 4，见 P1-4 那节）。

补的是 §2 表里"多中心"这个真空缺。**一处连带变更**：`RevealMaskSpec.maskRepeat` 的类型从 `'no-repeat' \| 'repeat'` 放宽成 `string`——多层蒙版要按层数逗号拼接，收窄成两个字面量表达不了；各层具体取值由单测锁死。

### P1-4 `BLINDS` 交错开合 → 落地为 `COMB` → 已撤回

| 项 | 内容 |
| --- | --- |
| 观感 | 奇数叶与偶数叶分两批错开揭开。候选池当时写"中间出现一批已封顶、另一批刚起步的高对比态，BLINDS 全程到不了这个画面"——**这句是错的**，那一帧恰好等于 BLINDS 在 `slatWidth = 2W` 时的某一帧 |
| 机制增量 | **无**（两层条带 + 错时）；`orchestrate.ts` 与 `styles.ts` 零改动，只加守卫一个 `\|\|` 与分发一个 `if` |
| 实现要点 | 奇偶批各一层条带渐变，周期 `2 × slatWidth`，`from = -feather` / `to = stagger + slatWidth`，`add` 并集。零新选项（复用 `direction` + `slatWidth`） |
| 待验点 | **三条实测结论**：① 钳值只能 `min()`、不能加 `max(..., 0px)` 下界——钳到 0 会让 `#000 0 0px → transparent f` 在起始帧每片叶片左沿留一条实边漏光；允许取负才能把整段推出平铺边界。② 交错量比例取 1 时退化（奇数段 `0..W` 与偶数段 `W..r` 拼成单条 `0..r`）；取 0.5 是 `s(W−s)` 这个"对比度 × 窗口长度"乘积的**最优点**，也就是说这条路上已经没有更好的取值了。③ 补救方案"反向生长"（奇数从左沿长、偶数从右沿长）**数学上必然退化**：偶数段 `[2W−c, 2W]` 与下一周期奇数段 `[2W, 2W+c]` 在 tile 边界首尾相接合并成单段 `2c`，每周期只剩一段实心带 = BLINDS@2W，加错时也救不回来 |
| 量化判据 | 扫描线 run-length 签名（O=不透明段，周期 144px，r=48）：现版 COMB `O58 .14 O22 .50`（每周期**两段不等宽**，结构上确实区别于任何单一 slatWidth 的 BLINDS）；反向 COMB `O58 .38 O106 .38` 与 BLINDS@144 `O116 .28 O116 .28`（都是每周期**一段**）。**但**两批同时在生长的窗口只占时长 31%（236ms / 750ms，按 `cubic-bezier(0.42,0,0.58,1)` 反解），其余 69% 只有一批在动 |
| 状态 | **已撤回（2026-09-24）**。需求方真机反馈"基本和 BLINDS 差不多"，量化后成立：唯一的区别是带的宽窄比例，那是静态属性，750ms 不给解析时间，而且 BLINDS 自己的 `slatWidth` 滑杆覆盖 16..200，任何条纹节奏差异都能被读成"换了个叶宽"。**撞新加的约束 4**（任意单帧必须能与同类项区分）。源码走 `git revert`，历史保留 |

**这一节留下两样东西**：一是约束 4 这条判据（同时回头解释了 `SPIRAL`）；二是"条带一族身份轴已用完"的结论——BLINDS 等宽同步 / SCAN 单层擦除 / QR_GRID 二维逐格 / CURTAIN 中线对称，已经把"一维条带能表达的静态图案 × 推进方式"占满，不要再回来。

**流程上仍然有效的一半**：这轮把观感预检提到写库代码之前，前两个问题（`max()` 漏光、`stagger=1` 退化）确实都在动源码前抓到了。但**预检漏掉了最贵的那个**——我只看了 COMB 自己的静态帧，从没和 BLINDS 同时间轴并排比过。所以预检的正确姿势是**新变体必须和同类项放同一条时间轴上做 A/B**，单独看它自己长什么样没有意义。

### P2-1 通用反向 `reverse`

| 项 | 内容 |
| --- | --- |
| 观感 | 让中心扩散与属性驱动类都能"反向揭开"（新主题从四周显出、向触发点收拢），收益 = 观感近乎翻倍 |
| 机制增量 | 分路线看：属性驱动族（`FAN` / `RIPPLE` / `CLOCK_SWEEP`）是**蒙版求补 + 动画反向**，盒子仍静止；`CIRCLE` 复用已有的洞式生成器。~~形状族只是 SVG 加一个反色开关~~ —— **这句是错的**，形状的洞只能靠动 `mask-size` 来收，会踩回抖动病根（见 §4） |
| 卡点 | ~~`CIRCLE_REVERT` 会同时存在"类型"和"选项"两种写法~~ —— **已解**：选项取 `boolean \| 'auto'` 三态，`'auto'` 就是当时 `CIRCLE_REVERT` 的"跟随切换方向"语义。纯布尔删不掉那个类型，因为布尔的两个值都不等于它——`toDark` 只决定 `collapse` 的一个分支条件，两种布尔值都不是"跟随" |
| 参数面 | 一个三态选项，实际接入 **5 个类型**。`BLINDS` / `SCAN` / `QR_GRID` 不开是`direction` 已占那根轴；形状族不开是做不到无副作用（§4） |
| 状态 | **PR1–PR4 全部落地（v1.10 – v1.13，攒进 0.4.0）**：`CIRCLE` / `FAN` / `RIPPLE` / `CLOCK_SWEEP` / `CURTAIN` 五个接入，`CIRCLE_REVERT` 已在 PR4 删除。`CURTAIN` 一度被判"做不到"，那是**只试了单渐变**的错判，两层 `add` 构造可解。只剩形状族 6 个真的做不到（§4）。判据与分期见 `docs/reverse-option-design.md`。**2026-09-28 复盘**：「形状族做不到」收窄为「动 `mask-size` / `mask-position` 这条路做不到」——静止盒子 + 渐变补集（CURTAIN 反向同路数）可无副作用接入 `SQUARE` / `RECTANGLE` / `CIRCLE_BLUR` / `DIAMOND`，立 P3-7 / P3-10；`SCAN` / `BLINDS` 不接入的理由记 §4 |

### P2-2 `LOGO_MASK` 自定义轮廓

| 项 | 内容 |
| --- | --- |
| 观感 | 新主题以用户给的图形轮廓（logo、心形、任意 path）揭开 |

### P3-9 QUAD 十字四向（预检门槛 → 条件落地）

| 项 | 内容 |
| --- | --- |
| 观感 | 新主题自屏幕中心向四向同时揭开：水平 / 垂直两条中缝先透光，十字缝随推进向外退。静态帧拓扑 = 十字缝 + 四象限，CIRCLE / SQUARE / CURTAIN 都给不出这个画面（过约束 4 的依据） |
| 机制增量 | 一层 `intersect` + `@supports` 基线降级（QR_GRID 路子，基线降级观感 = CURTAIN）；反向 = 四层边缘板 `add`（免 `@supports`） |
| 实现要点 | 正向 = `centerBandGradient(90)` ∩ `centerBandGradient(180)`——两个构造器都已在码上（CURTAIN 主层与 QR_GRID 垂直轴层共用）。反向是它的补集 = 四块边缘板并集（∩ 的补 = 补的 ∪），即 CURTAIN 反向两层串的正交复用。**共享 var 必须按轴归一**：水平轴要走到 `宽 + 2 × 软边`、垂直轴要走到 `高 + 2 × 软边`，`centerBandGradient` 需加轴缩放因子（`calc(var × k)`，length × number 合法）——不然一轴先走完、后半程只剩单轴在动（COMB 式死区） |
| 参数面 | 无触发点、`direction` 静默、接入 `reverse`（同 CURTAIN 口径） |
| 待验点 | **先预检后写库代码**：jitter-lab 与 CIRCLE@中心 / SQUARE@中心 / CURTAIN 同时间轴 A/B（P1-4 的教训：必须和同类项并排比，单看自己没有意义），判据 = 十字缝是肉眼可读的身份特征；不绿整个撤回并记 §4。绿了按 §5 顺序 core + 画廊先行；涉及解冻，实现开工前在 requirements §10 补修订记录 |
| 状态 | **已撤回（2026-09-28，预检否决，未碰 core）**。按 §5 约定只在预检阶段花了成本：候选 CSS（`centerBandGradient(90) ∩ centerBandGradient(180)` + 轴归一 `calc(var × 0.6386)`，`@property` 驱动）在 jitter-lab 与 CIRCLE@中心 / SQUARE@中心 / CURTAIN 同时间轴 A/B，**帧证据判了死刑**——中段帧（t=281/375）渲染的是「居中暗矩形 + 四周对称光边」，与 RECTANGLE / SQUARE@中心的"中心形状生长 + 光边"拓扑无法区分；预定义的十字缝身份判据（垂直缝对比度 ≥30 vs 三同类项 ≤15，≥3 帧命中）0/5 命中。**根因是构造级的**：intersect（roadmap 原规格）的缝 = 两带交集的边界 = 矩形光圈，"十字"只在起始 ~100ms 的两条羽化线交叉处一闪而过；而能给出真十字（两条带 `add` 并集，全程贯穿屏幕的加号）的构造**末帧是十字不是整平面，直接违反约束 2**。"十字缝 + 四象限"的静态拓扑在这两条路上都拿不到。与 P1-4 同一条教训的第二次应验：QUAD 单独看完全像一个新的合法类型（覆盖、推进、单调全过），和同类项并排比才暴露身份缺失——预检门槛再次值回票价 |

## 4. 明确不做（防止重复讨论）

| 候选 | 否掉的理由 |
| --- | --- |
| 3D 翻页 / 折叠 | 要放弃 mask、改动画 `::view-transition-group` 的 transform，直接破约束 1；且 `masks.ts` 已记录 Safari 忽略伪元素上的 WAAPI 与 clip-path |
| 文字 / 描边书写揭示 | 越界（不是"主题揭开"而是内容动画），且蒙版尺寸随视口变化会失真 |
| `DISSOLVE` 沙化溶解 | 撞约束 2：噪声天然留镂空，末帧洗不干净。要绕开得做"实心段 ∪ (噪声 ∩ 前缘带)"三层 + per-layer composite，比涟漪高一档以上，且 per-layer composite 的支持面比 QR_GRID 现在用的单层 intersect 更窄 |
| `PIXELATE` 随机马赛克 | CSS 表达不了"随机顺序"，为每格准备属性的话图层数与属性数一起爆 |
| 真·水面折射位移 | 撞约束 3：转场期只有伪元素能动，`feDisplacementMap` 位移做不了（`RIPPLE` 只能是"环形蒙版揭示"） |
| 边角擦入 / 对角展开 | 观感接近 `SCAN` 的参数变体，该作为 `direction` 的新取值或 `origin` 选项，不占类型名额 |
| 继续加多边形（八边形、十字、心形…） | 形状族已 7 个饱和，边际观感收益接近零 |
| `SPIRAL` 螺旋旋掠（conic ∩ radial） | **实现过、真机否决**（2026-09-23）：技术全通（双层 intersect 渲染、两个 `@property` 同 keyframes 各自插值、末帧盖满都实测成立），但"一条射线 + 一段圆弧外沿"读起来仍是"扇形在转"，与 CLOCK_SWEEP 区分度不足。详见 P0-2 那节的根因分析 |
| `SEEDS` 多点错时渗透 | **实现过、真机否决**（2026-09-23）：`min()` 钳制修好了"只有两个格"的缺陷、四点层次实测可见，但圆斑越界交叠读起来像"气泡互吞"不像"渗透"。多中心方向在纯 CSS 蒙版下是天花板，别再试第二遍 |
| `reverse` 接入形状族其余 3 个（`HEXAGON` / `TRIANGLE` / `STAR`）——**整行已收窄**：`SQUARE` / `RECTANGLE` / `DIAMOND` 已在 v1.14 / v1.16 经「静止盒子 + 渐变补集」接入（见 §3 P3-7 / P3-10），不再适用本行 | 设计阶段曾判"反色一处开关、成本≈0"，实现前反证**不成立**：形状蒙版是 SVG data-URI，直接反向必须动 `mask-size` / `mask-position`，而那是 phase-6 附录四/五排查过的**设备像素对齐抖动**病根（约 1 设备像素、与 dpr 无关、取整只缓解），当初正是为此才另造静止盒子的洞式方案。多边形硬直线比圆弧更显 hairline。静止盒子绕路只对轴对齐洞边界（方 / 矩）与对角条带洞（菱）成立，对斜线轮廓的一般情形不成立，故这 3 个做不到无副作用 |
| `COMB` 梳齿交错（条带分批错时 / 反向生长） | **实现过、真机否决**（2026-09-24）：撞约束 4。现版（奇偶错半拍）扫描线签名是每周期两段不等宽实心带，结构上确实不同于任何单一 slatWidth 的 BLINDS，**但两批同时在生长的窗口只占时长 31%（236ms / 750ms）**，其余 69% 只有一批在动 = 等效"叶宽 2W 的 BLINDS"，而 BLINDS 的 slatWidth 滑杆本来就覆盖 16..200。补救方案"反向生长"经实测**数学上必然退化**：偶数段 `[2W−c,2W]` 与下一周期奇数段 `[2W,2W+c]` 在 tile 边界首尾相接合并成单段 2c，每周期只剩一段，就是 BLINDS@2W——加错时也救不回来。**结论：条带一族的身份轴已用完**（BLINDS 等宽同步 / SCAN 单层擦除 / QR_GRID 二维逐格 / CURTAIN 中线对称占满了"一维条带的静态图案 × 推进方式"），别再回来 |
| `QUAD` 十字四向（两中缝 ∩ / add） | **预检否决、未实现**（2026-09-28，P3-9）：`centerBandGradient(90) ∩ centerBandGradient(180)` 的中段帧是「居中矩形 + 对称光边」，与 RECTANGLE / SQUARE@中心的静态拓扑无法区分（十字只在起始 ~100ms 的羽化线交叉处一闪而过）；能给出真十字的 `add` 构造末帧是十字不是整平面，违反约束 2。"十字缝 + 四象限"的静态拓扑在 intersect / add 两条构造上都拿不到，帧证据见 §3 P3-9 那节 |
| `reverse` 接入 `SCAN` | 补集扫开与四向 `direction` 的镜像完全重合，零观感信息量，不值得开 |
| `reverse` 接入 `BLINDS` | 「叶片合拢」推演必然退化：每对半叶在 tile 边界首尾相接合并成单段实心带 = BLINDS@2W（同 COMB 反向生长的退化路径），且 `direction` 已占那根轴 |
| 斜向菱形格网 | = QR_GRID 换旋转角的参数变体，撞约束 4；真要斜向应作为 QR_GRID 的参数而不是新类型 |
| 波浪 / 有机边圆形 | 读起来是 CIRCLE 的贴图变体（约束 4）；有机边要逐点烘进渐变串，成本与辨识度不成比例 |
| SCAN 中心起扫 | 静态帧 ≈ CURTAIN 加前缘光束，约束 4 区分不开；「自中心揭开」的缺口由 QUAD（P3-9）覆盖 |
| FAN 旋转中旋开 | 轴自转 × 角度推进 = 时间维度装饰，重蹈 SPIRAL 的教训：750ms 内自转读不出 |

## 6. 每加一个类型的固定成本

一个类型从落地到文档齐平，硬编码数字要改的地方：文档站 hero 两处、features、`site.ts` SEO、四个 playground 的"N 个按钮"。README 自 v1.9 起不再写死数字（只剩「动画类型」表追加一行），README 门面截图已随 0.5.1 宣传片封面改版取消（hero 改内嵌宣传片，与文案互不带动），"hero 一改就得重拍截图"的成本随之消失。

两个减负方向都已落地：

- README 特性清单不写死数字，只列家族（"圆形 / 形状 / 条带格子 / 环带 / 角度"），数字只留在文档站 hero（v1.9 起）
- 门面同步攒批押后，不逐项摊开（既定做法，见 `next-steps.md` §1 总原则）
